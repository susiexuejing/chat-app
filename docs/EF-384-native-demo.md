# EF-384：现有 Expo 应用内的合成闭环

关联 [EF-384](https://douhaoyu.atlassian.net/browse/EF-384)。实现基线为 dev `392161d20f86bb2d710a8cb6a25e32253dff6b5a`；业务规则参考 PR #160 `519b67ddc476751c43f76f439ddeb5ed75cee701`。本次是 React Native / Expo 页面与仓储移植，不加载独立 HTML、iframe 或 WebView，不继承独立 HTML 的 QA 结论。

## 运行边界

- 原有 `/` 和 `/chat` 入口保留。现有 DEV 导出使用 `EXPO_PUBLIC_APP_ENV=DEV`，在根布局挂载 Provider 之前选择合成运行。
- DEV 运行不挂载真实 `ChatProvider`，不启动其历史水合、会话恢复或发送请求。原有 Provider、global.css 和页面容器保留；非 DEV 构建继续使用原有聊天页面和 ChatProvider。
- 合成页面只使用独立仓储，不读取或改写 `chat_sessions`、真实会话或模型配置。数据不离开当前浏览器。
- 本阶段面向现有 DEV 网页。SSR 先显示加载状态，浏览器挂载后才访问 localStorage；本地存储不可用或非 Web 平台明确阻断，不降级到真实聊天或声称已持久化。
- 仅支持一个活动标签页。同步 localStorage 的单项写入保证同一次变更的聚合一致性；版本检查不等同于跨标签页事务锁，不声称多标签并发安全。

## 业务范围

使用虚构号码 `00000000000` 和当次页面显示的六位演示码，不发短信。固定合成聊天只生成待观察候选；拒绝、暂不确定、停止、离开与取消不保存候选或草稿。

一个模式对应一个可编辑/暂停的练习。记录按是否发生、实际动作和相关感受展开，保留“其他动作”和“不想记录感受”，跳过不写入，备注不必填。路径回看显示明确保存的事实、来源、记录和理解修正；感受/说明可编辑，移除关联须确认。例外类型的显示与可由用户创建例外的能力分开，本次不新增例外创建流程。

仓储以带版本的独立聚合保存本地演示账户、会话、模式、练习、记录与路径。理解变化和旧/新理解历史一次提交，记录和路径关联一次提交。失败不会把部分结果当成功，草稿由页面保留以便重试；取消与退出清空未保存界面状态。操作标识用于重复记录提交的幂等校验。已丢失的旧理解不会补造。

BQA-01：页面提示属于当前操作。开始新的操作、编辑或导航时清除旧成功提示；失败显示当前未保存状态，不能同时遗留旧“已保存”。

## 验证与交付

本分支新增 `EF-384 Native Demo Verification`，仅运行测试与导出构建，不部署，权限为 contents:read：

1. 精确 PR head 校验与 frozen-lockfile 安装。
2. `node --test scripts/__tests__/ef384-native-*.test.cjs`（仓储事务及静态隔离检查）。
3. 全量 client Jest（包含新原生边界/页面测试和旧聊天回归）。
4. client TypeScript 与 ESLint。
5. `EXPO_PUBLIC_APP_ENV=DEV` Expo web export。
6. runtime-data 检查与仅供审查的构建附件。

具体执行结果以固定提交的 CI/QA 回执为准。新的原生浏览器、视觉、焦点、实际存储/CSP、Back/Forward 和 DEV 回归均须另行验证，不能用独立 HTML 的旧结果替代。通过前不标整票完成，不交用户充当独立 QA。

## 发布限制和回退

本次只提交独立 feature branch / draft PR，不修改准入规则，不合并、不部署。现有 `deploy-dev.yml` 的 dev push 会同步整个前后端并重启 PM2，不是只发布这些客户端文件。发布前须确认真实准入要求并处理失败检查；不能用候选分支自签受保护登记。

后续若获准发布，应固定合并提交，沿用现有备份/回滚流程，核对前端 deployment SHA、后端 version/health 与旧入口，然后在实际 DEV 复验闭环。代码回退为撤销本票 client 改动；本地合成命名空间与真实聊天数据隔离，不自动删除用户浏览器数据。任何 DEV 发布/回退的后端影响均需按现有流程核实。
